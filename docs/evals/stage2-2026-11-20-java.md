## 다시 요청 4번의 원인과 #183

실행 1의 다시 요청 4번은 모두 `symbol_id: string_too_long`이었습니다.
꼬리질문의 심볼 id(`PreparedFollowup.symbol_id`)가 100자까지였는데, Java 메서드 id는 패키지 경로 때문에 100자를 넘습니다(예: `.../owner/PetController.java::PetController.processCreationForm`, 107자).
LLM이 관련 메서드를 제대로 골라도 거부되어 다시 요청했고, 다시 요청하면 id를 비워서 꼬리질문 대부분이 코드 강조를 잃었습니다.
#183에서 200자(심볼 id와 같은 길이)로 맞추고 다시 돌린 실행 2는 다시 요청 0번, 꼬리질문 12개 모두 관련 메서드를 가리켰습니다. 비용도 절반으로 줄었습니다.
