# 검토 근거 문장 대조 평가 (2026-11-21)

- 이슈: #206
- 출제·검토: `gpt-6.2-sol` (출제 추론량 low, 검토 medium), BizRouter 경유
- 레포: `tttae210-sys/gitinsight_agent` @ `6a3111ce7e36918a4332d63e25d59e471961879f` (샘플 데모 레포)
- 비용은 BizRouter 과금 값이고 원화로 봅니다 (#201).

## 왜 돌렸나

#201 비교에서 검토를 gpt-6.2-sol로 돌리자 "낸 근거가 자료에 없음"(`bad_quote`)이 나왔습니다.
근거가 떨어진 요점은 검토 LLM이 통과라고 해도 고칠 것이 되어, 출제 LLM이 다시 만듭니다.
그래서 근거를 잘못 옮긴 것만으로 재출제와 재검토가 늘고 분석 시간과 비용이 커집니다.

## 1. 원인 (고치기 전, 2회)

| 실행 | 낸 근거가 자료에 없음 | LLM 호출 | 분석 전체 시간 | 비용 | 버린 후보 |
|---|---|---|---|---|---|
| 1 | 0 | 20 | 174초 | 463원 | 1 |
| 2 | 14 | 36 | 267초 | 827원 | 3 |

같은 조건인데 2회차만 근거가 14건 떨어졌고, 호출 수와 시간이 그만큼 늘었습니다.
대조에서 떨어진 근거를 모아(평가 스크립트에서만, 운영 로그에는 남기지 않음) 유형을 나눴습니다.

| 유형 | 건수 |
|---|---|
| 떨어진 여러 줄을 한 인용으로 이어 붙임 (줄마다는 코드에 그대로 있음) | **14** |
| 10자보다 짧음 | 0 |
| 따옴표·백틱 같은 기호만 다름 | 0 |
| 생략 기호(…)로 중간을 줄임 | 0 |
| 글자가 조금 다름 | 0 |
| 자료에 없는 문장 | 0 |

예: `has_resume = bool(resume_text)` 줄과 수십 줄 아래의 프롬프트 문자열 줄을 한 인용으로 붙였습니다.
서버는 인용을 통째로 대조해서, 각 줄이 코드에 있어도 떨어뜨렸습니다.

## 2. 바꾼 것

- 여러 줄 근거는 통째로 없어도 줄마다 대조합니다(`review.py`의 `quote_in_source`).
  모든 줄이 자료에 글자 그대로 있고, 그중 한 줄이 10자 이상이면 인정합니다.
- 한 줄이라도 자료에 없으면 지금처럼 떨어집니다. 줄마다 글자 그대로여야 해서, 코드에 없는 이유를 덧붙인 문장을 거르는 목적은 그대로입니다.
- 짧은 근거(`short_quote`)를 자료에 없는 근거(`bad_quote`)와 나눠 셉니다.

## 3. 바꾼 뒤 (3회)

| 실행 | 낸 근거가 자료에 없음 | 근거가 짧음 | 근거를 내지 않음 | LLM 호출 | 분석 전체 시간 | 비용 | 버린 후보 |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 0 | 2 | 20 | 169초 | 431원 | 0 |
| 2 | 0 | 0 | 3 | 22 | 165초 | 492원 | 0 |
| 3 | 0 | 0 | 3 | 18 | 142초 | 390원 | 0 |

- 근거 151개 중 9개가 줄마다 대조로 인정됐습니다. 예전 규칙이었다면 요점 9개가 재출제됐습니다.
- 3회 모두 떨어진 근거가 0건이고, 분석 전체 시간이 142~169초로 고치기 전(174초, 267초)보다 짧고 고릅니다.
- 3회 모두 버린 후보가 없습니다.

## 4. 오류를 여전히 잡는가

11-18 평가에서 사람이 찾은 오류가 든 재료 2개를 같은 커밋 코드와 함께 5번씩 검토에 넣었습니다(#199 평가 1절과 같은 방법).

| 재료 | 사람이 찾은 오류 | 잡은 횟수 |
|---|---|---|
| `git.py::git_cloner` | 요점 4: 코드와 반대 | 5/5 |
| `store.py::InMemoryAnalysisStore` | 요점 3: 코드에 없는 이유 | 5/5 |

대조를 넓힌 뒤에도 10/10으로, 고치기 전(#201, 10/10)과 같습니다.

## 결론과 남은 것

- 근거가 떨어지는 원인은 떨어진 줄을 이어 붙인 인용 하나였고, 줄마다 대조로 해결됐습니다.
- 예전 규칙에서는 실행마다 0~14건으로 편차가 커서, 이번 3회의 0건도 운이 좋은 것일 수 있습니다. 운영 로그의 `bad_quote`, `short_quote` 개수로 계속 봅니다.
- "근거를 내지 않음"(2~3건)은 이번 변경과 관계없이 남아 있습니다. 검토 LLM이 요점에 근거를 대지 않은 경우라 재출제가 맞습니다.
- 레포 1개, 실행 5회(고치기 전 2, 뒤 3)라 비율은 참고용입니다.
